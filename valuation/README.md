# 2027 국내주식 밸류에이션 자동화

## 운영 정책 (2026-10-30)

- 실제 전송은 작성일 당일 KST의 KRX 정규장 15:30 종가만 허용합니다. 11:30·15:00 분봉, 현재가, 전일 가격으로 대체하지 않습니다.
- 평일 16:17 KST에 실행하고 18:17에 미전송 건만 재시도합니다. 예약 시작 시각은 GitHub 사정으로 지연될 수 있습니다.
- 자정을 넘겨 전일 회차로 해석되는 예약 실행은 API 호출 없이 종료합니다. 과거 거래일은 dry-run 검증만 가능합니다.
- 휴장일에는 전송하지 않으며, 휴장 판정을 ledger에 저장해 후속 회차의 휴장 조회도 생략합니다.

## 가격 검증 및 API 호출

1. 동일 날짜의 `YYYYMMDD_close` ledger를 먼저 조회합니다. `sent`, `sending`, `market_closed` 기록이 있으면 시세 API 호출 전에 종료합니다.
2. KIS 휴장일 API로 정확한 거래일을 확인합니다. 한 실행에서 발급한 토큰을 재사용합니다.
3. KRX 코스피·코스닥 일별매매정보를 각각 한 번 조회합니다(정상 응답 기준 총 2회). 응답 `BAS_DD`가 대상 날짜와 일치한 행만 인정합니다.
4. 모든 대상 종목의 종가와 상장주식 수를 확인합니다. 누락·날짜 불일치 시 전송하지 않고 다음 예약을 기다립니다. 종목별 반복 조회나 분봉 대체를 하지 않습니다.
5. 엑셀 생성 후 기존 수식·계산 검증에 더해 파일의 거래일, 종목코드, 원자료 가격·주식 수·출처·종가 기준을 다시 읽어 대조합니다.
6. 전송 직전에도 KST 당일 여부를 재확인합니다. 검증 결과와 ledger 키는 artifact `run.json`에 남깁니다.

HTTP 429는 즉시 중단하며 같은 실행에서 재호출하지 않습니다. 인증 실패 등 영구 오류도 반복하지 않습니다. 일시적인 5xx/네트워크 오류는 요청 단위의 제한된 재시도만 사용하고, 전체 수집을 재실행하는 중첩 재시도는 없습니다.

## 중복 방지

모든 실행은 `krx-valuation-delivery` concurrency 그룹에서 직렬 처리합니다. `valuation-delivery-ledger` 브랜치의 `valuation-sends/YYYYMMDD_close.json`에 전송 전 `sending`, 성공 후 Telegram message ID와 `sent`를 기록합니다. 전송 결과가 불확실하면 자동 재전송하지 않습니다. 명시적 수동 `resend`만 기존 기록을 우회합니다.

## 수동 검증

Actions → KRX 2027 valuation → Run workflow에서 `slot=close`만 선택할 수 있습니다. 기본은 `dry_run=true`입니다. 과거 날짜의 검증은 가능하지만 실제 전송은 당일만 허용합니다. 템플릿 가격 fixture는 dry-run 전용입니다.

## 데이터 및 테스트

133종목 템플릿과 이익 추정치·ROE·메모·YoY 계산은 보존합니다. 가격이 검증돼도 이익 추정치가 없으면 PER/POR은 미산출입니다. 신규 추정치는 해당 종목코드 행에 입력합니다.

```sh
pip install -r valuation/requirements.txt
python -m pytest valuation/tests -q
```

실제 시세/Telegram API를 호출하지 않는 테스트로 날짜·세션 검증, 일괄 조회 횟수, 429 중단, 자정 지연 실행, ledger 중복 차단, 엑셀 계산을 검증합니다.
